系统架构

平台采用多层闭环联合仿真思路：水力状态经传感器与采集通道进入控制层，PLC 基于控制逻辑更新执行器动作，动作再反馈给水力计算模块。网络层对通信过程提供仿真环境。

逻辑分层

层级 主要模块 关注的问题
物理层 DHALSIM-epynet / EPANET 水位、压力、流量等状态演化
控制层 OpenPLC PLC 输入、控制逻辑、执行器指令
监控层 SCADA 通信与采集 数据上报、下发和缓存
网络层 ns-3 + Linux Network Namespace 拓扑、链路状态、通信扰动
编排层 Python 运行器 配置、进程启动、同步、结果导出

一个典型闭环

  1. 读取当前水力状态与传感器变量。
  2. 将观测数据通过通信路径送入 PLC / SCADA 相关模块。
  3. 执行 PLC 控制逻辑，确定泵阀等动作。
  4. 将新的控制动作作用于水力系统，并推进仿真步。
  5. 保存日志与状态，为下一轮控制提供输入。

上述流程是对研究架构的概念性说明，具体执行顺序应以运行器源码为准。

代码入口

  • scripts/run_all.sh：示例运行的总调度脚本。
  • src/network/：网络拓扑和运行环境生成相关模块。
  • src/control/：PLC 程序生成、编译和运行相关模块。
  • src/runtime/：闭环同步与运行时逻辑。
  • src/io/：实验数据导出。

详见公开仓库中的 run_all.sh。
